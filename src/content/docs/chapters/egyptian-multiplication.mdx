## 一张给书吏使用的数学文本

莱因德数学纸草书以购得它的苏格兰古物收藏家 Alexander Henry Rhind 命名，纸草书本身则署有书吏 Ahmose（也常译作 Ahmes）的名字。大英博物馆将其描述为很可能供书吏通过范例学习解题的数学文本，包含除法表、乘法、分数、面积与体积等八十余个问题。

纸草书的绝对年代在编年与目录表述中并不完全统一；本书保留一个约略区间，而不把某一年写成无争议事实。比日期更重要的是它提供了一种罕见的窗口：我们能看到答案，也能看到把答案一步步制造出来的书写程序。

古埃及数字是十进制的加法式记号，但这不意味着乘法一定采用今天学校里的竖式。许多计算可以从一种极其稳定的动作开始：**加倍**。若会把一个数加给自己，就能依次得到它的 2 倍、4 倍、8 倍……；再挑选若干行相加，就能拼成需要的倍数。

## 从数量任务到加倍表

假设一份配给含 23 个单位，要准备 18 份。现实任务可以抽象成整数乘法 `23 × 18`。我们暂时假定每份完全相同、数量没有测量误差，也不考虑无法整分的余量。

先同时建立两列：左边从 1 开始，右边从 23 开始，每一行都把上一行加倍。

| 份数 | 物品数 | 是否取用 |
| ---: | ---: | :--- |
| 1 | 23 |  |
| 2 | 46 | ✓ |
| 4 | 92 |  |
| 8 | 184 |  |
| 16 | 368 | ✓ |

因为 `18 = 16 + 2`，就在右栏选择同样的两行：

```text
23 × 18 = 23 × (16 + 2)
        = 368 + 46
        = 414
```

这里真正发挥作用的是乘法对加法的分配律。加倍表不是记忆乘积的技巧，而是把一个较大的乘法拆成一串规则一致的小动作。

可以试试这些输入：

- `27 × 32`：只需要选择一行。
- 交换两个乘数：答案不变，但加倍表的行数可能改变。

第三个现象揭示了实现选择。数学上 `a × b = b × a`，但若把较小的数放在负责分解的左栏，通常需要更少的加倍行。相同公式可以对应不同成本的程序。

## 为什么每个正整数都拼得出来？

从 1 开始不断加倍，会得到 `1, 2, 4, 8, 16, ...`。任意正整数 `n` 都能写成互不重复的这些数之和。可以用一个递减过程看见这一点：

1. 取不超过 `n` 的最大 2 的幂。
2. 从 `n` 中减去它。
3. 对剩余的更小非负整数重复；余数为 0 时停止。

每次余数都严格变小，所以过程必然结束。所选的幂也不会重复，因为取走最大一项后，余数比它小。

今天我们会把“选择了哪些 2 的幂”写成二进制位。例如 `18` 的二进制是 `10010₂`，正好标出 `16` 与 `2` 两行。但这只是**现代结构解释**：它不证明古埃及书吏在使用位置制二进制记数，更不证明现代计算机的二进制由此直接传承而来。

## 每一步保存了什么？

令每一行左边为 `w`、右边为 `p`。表从 `(1, a)` 开始，并把两边同时加倍，所以始终保持：

```text
p = a × w
```

如果选择若干行，分配律给出：

```text
右栏之和 = Σ(a × w) = a × Σw = a × 左栏之和
```

因此，只要左栏之和拼成乘数 `b`，右栏之和就必然等于 `a × b`。这就是算法正确性的核心证明；无论数字多大，都不依赖某一次计算碰巧算对。

## 它需要多少工作？

若乘数是 `b`，加倍到不超过 `b` 的最大 2 的幂，需要大约 `log₂ b` 次加倍。随后至多选择同样数量的行进行累加。和把 `a` 连加 `b` 次相比，步骤增长慢得多。

但“每次加法成本相同”也是模型简化。数字越大，书写和相加本身越费力；在真实纸草书上，版面、抄写错误和核验方法同样构成成本。现代复杂度分析会进一步区分“算术操作次数”与每次大整数运算的位数成本。

## 模型何时需要扩展？

这个实验只接受 1 到 255 的正整数，是为了让表格保持可操作。历史计算当然还包括分数；莱因德纸草书尤其以单位分数表和分数运算闻名。把整数方法直接套给面包、土地面积或容量时，还需要先规定计量单位、分割规则与舍入方式。

负数、零、溢出和测量误差也没有出现在当前模型中。扩展到现代机器整数时，加倍可能越过可表示范围；扩展到实测数量时，`23` 可能只是四舍五入后的读数。算法可以继续运行，但输入代表什么必须另行验证。

## 现实回声：一种结构，多种实现

“一边加倍、一边分解”的结构后来以不同形式反复出现。所谓俄罗斯农民乘法会让一边加倍、另一边折半，并按奇偶选择行；现代计算机中的移位加法乘法也利用 2 的幂展开。它们在数学上相亲，却不能仅凭相似就断言存在一条未经史料证明的直接传播链。

更广泛地说，预先建立容易生成的“积木”，再选择少量积木拼出目标，是算法设计的常见策略。快速幂用平方序列拼指数，二进制分解帮助组织集合，编码与数据结构也不断利用这种层级倍增。
