# 技术路线

## 目标

这不是把纸书搬到网页，而是建立一套可持续写作的互动出版系统。正文、史料、公式、实验、练习和引用需要能够独立演进；每章还必须拥有稳定、可分享的 URL。

## 总体选择

- **应用外壳：** vinext + React + TypeScript。保留服务端渲染和按章节路由，首次打开即可阅读，互动部分再在浏览器中接管。
- **内容层：** MDX。普通叙事保持接近 Markdown，实验、时间线、史料卡和练习作为组件嵌入正文。
- **算法内核：** 无界面的纯 TypeScript 函数。算法不直接操作图形，而是输出标准化的步骤事件。
- **表现层：** React 消费步骤事件；离散结构优先使用 SVG，密集粒子和连续模拟使用 Canvas，只有确有必要时才使用 WebGL。
- **发布：** 每章独立路由，部署到边缘网络；默认不需要数据库或登录。

## 最关键的架构约束：算法与动画分离

每个实验分成三层：

1. `core` 接收输入并产生确定性的步骤事件。
2. `player` 负责播放、暂停、回退、速度和分享状态。
3. `view` 把同一组事件画成几何、表格、波形或网络。

例如欧几里得算法不应调用“把蓝条缩短”之类的视觉指令，而应产生：

```ts
{ type: "divide", dividend: 252, divisor: 105, quotient: 2, remainder: 42 }
```

这样同一算法可以拥有长度条、古希腊几何、伪代码高亮和无障碍文字四种视图，也能独立测试正确性。

## 建议目录

```text
app/
  chapters/[slug]/       章节路由与分享元数据
components/
  book/                  脚注、史料卡、公式、时间线
  labs/                  播放器和领域视图
content/
  chapters/              MDX 正文
  sources/               书目与史料元数据
lib/
  algorithms/            纯算法及步骤协议
  exercises/             判题器与提示策略
  sharing/               URL 状态的编码与恢复
public/
  figures/               有授权记录的静态资料
tests/
  algorithms/            性质、边界和回归测试
  chapters/              链接、引用和元数据检查
```

## 互动学习能力

- 所有实验支持单步、回退、重置和自定义输入。
- 重要状态编码进 URL；读者可以分享“某组输入的第七步”，而不只是分享章节首页。
- 学习进度、阅读模式和草稿答案保存在本机；只有未来明确需要跨设备同步时才增加账户与数据库。
- 代码执行放入 Web Worker，避免长计算锁住页面。
- 第一阶段统一使用 TypeScript；需要展示 Python 时再按章懒加载 Pyodide，避免让每位读者承担大型运行时下载。
- 数学公式使用 KaTeX；可执行代码使用 CodeMirror；两者都按需加载。
- 每个图形实验提供等价文字描述和键盘操作路径。

## 内容与史料

- 每章将“可核查史实”“数学推导”“现代解释”分栏处理。
- 引用使用结构化书目数据，由构建过程统一生成脚注和参考文献。
- 图片记录作者、来源、许可和裁切说明；无法确认许可的材料不进入发布版本。
- 日期不确定时保留“约”“现存最早证据”等历史学表述，不把传播史写成单一发明者故事。

## 分享与发布

- 每章具备独立标题、简介和社交分享卡片。
- 默认页面服务端渲染，搜索引擎和关闭 JavaScript 的读者仍可看到正文。
- 初期保持无后端、可缓存、可离线化，降低维护成本。
- 正文和互动组件共用版本控制；每次发布都能对应到确定的史料和算法实现版本。

## 实施顺序

1. 固化章节数据模型、步骤事件协议和引用模型。
2. 把欧几里得样板章做完整：历史现场、实验、证明、练习与分享状态。
3. 再制作一个连续模拟型章节（如 Runge–Kutta）和一个重建型章节（如 CT），验证架构不是只适合数据结构。
4. 三种实验形态稳定后，再批量扩展目录和编辑工具。
5. 最后增加离线包、教师模式、跨设备进度等非核心能力。
